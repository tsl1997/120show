# 国内城市改造总计划（像海贼王一样分册推进）

> 目标：每个城市从"几个零散景点"改造成"一个完整立体的城市"——地点、美食、市井、历史、传说全覆盖。
> 方式：一城一城来，每城先写计划文档（打样城市武汉单独成文，其余城市在本文件内登记），再分册重构。
> 数据结构沿用三分册：spots（景点打卡）/ souvenirs（特色周边）/ stories（奇闻趣事）。

## 扩容执行大纲（以武汉为打样，按登记表自上而下逐城推进）

> **每城流程**：①读旧单文件 → 保留城市 id/名称/desc/travel，**保留既有条目 id**（存档兼容）
> ②在 `data/cn/<区域>/<城市id>/` 新建 `<前缀小写>_01_spots.js / _02_gifts.js / _03_stories.js` + `<城市id>.js` 组装器（window 全局用 `<前缀大写>_SPOTS/GIFTS/STORIES`，前缀全库唯一）
> ③把 index.html 中该城旧单文件引用替换为"三分册+组装器"四条引用
> ④`node check_data.js` 校验无错误 ⑤在登记表该行打勾并记录总条数。
>
> **体量目标**：spots ≈28-36 / gifts ≈30-38 / stories ≈28-34，合计 90-105 条，参照武汉 99 条。
> **写作纪律**：条目 id 全局唯一、描述带画面感且 ≥18 字、少用英文单词；tag∈衣/食/住/行/玩/游/闻，type∈美食/饮品/特产/文创/服饰/体验/住宿/宝物；城市要有"生活气"（早市、街区、方言、节庆、传说都要有席位）。
> **处理顺序**：西安→北京→成都→重庆→上海→杭州→南京→洛阳→广州→哈尔滨→拉萨→三亚→苏州→敦煌→大同→长沙→厦门→青岛→泉州→景德镇→贵阳→桂林→丽江→西双版纳→呼伦贝尔→喀什→乌鲁木齐→银川→兰州→西宁→平遥→承德→长春→沈阳→大连→天津→荆州→襄阳→黄山→泰安→绍兴→扬州→深圳→台北→香港→澳门→开封→漠河→张家界→呼和浩特→乐山（以实际文件清单为准）。

## 目录结构约定

```
data/cn/<区域拼音>/<城市id>/      ← 每城一个文件夹
├── <前缀>_00_plan.md            ← 城市改造文档（大城市单独成文，小城市在本文件登记）
├── <前缀>_01_spots.js           → window.<前缀>_SPOTS
├── <前缀>_02_gifts.js           → window.<前缀>_GIFTS（美食/特产/文创，tag∈衣食住行游玩闻）
├── <前缀>_03_stories.js         → window.<前缀>_STORIES（历史/传说/市井/节庆）
└── <城市id>.js                  ← 组装器（窗口数组拼成城市对象，id 不变，存档兼容）
```

## 写作纪律（防卡死三原则）

1. **一次只做一座城**：文档→分册→组装器→挂载→校验→登记打勾，然后才开下一座。
2. **城市要有"生活气"**：不止名胜，还要早市、街区、方言、节庆、传说——让玩家"住"进这座城市。
3. **tag/type 白名单**：美食/饮品/特产/文创/服饰/体验/住宿/宝物；描述≥18字，避免英文字母词。
