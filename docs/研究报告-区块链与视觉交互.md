# 120.show 项目研究报告：区块链（Web3）与视觉交互模块

> 研究范围：`web3/`、`airdrop/`、`text/`（区块链线）；`camera/`、`qifu/`（视觉交互线）
> 研究对象版本：仓库当前工作区快照

---

## 一、总体判断

`120.show` 是一个**纯静态、Zero Build、无后端**的个人实验站点。所有能力都靠浏览器原生 API + CDN 前端库在客户端完成，没有任何服务端参与。

两条线的性格差异很明显：

| 维度 | 区块链线 | 视觉交互线 |
|---|---|---|
| 核心技术 | ethers.js v6 / solc / viem / tronweb / @solana/web3.js | MediaPipe FaceMesh & Hands / Canvas 2D / React 19 |
| 交互媒介 | 钱包（MetaMask / 私钥）、RPC 节点 | 摄像头、人脸 / 手势 |
| 主要风险 | 私钥泄露、链上误操作 | 摄像头权限、模型 CDN 可用性 |
| 复用方式 | 每页自包含，配置集中在 `config.js` | 每页自包含，同款设计系统 |

一个贯穿全局的工程约定：**每个页面都是「单文件自包含」**——CSS 内联、JS 内联、依赖走 CDN。好处是单页维护、互相低耦合；代价是重复代码多、依赖版本容易漂移（后文会展开）。

## 二、区块链（Web3）部分

### 2.1 模块地图

`web3/index.html` 是合集入口，按 6 个分区组织：

- **测试网转账**：`transfer.html`（EVM 21 个测试网）、`transfer-trx.html`（TRON）、`transfer-sol.html`（Solana）
- **钱包生成**：`wallet-evm.html` / `wallet-trx.html` / `wallet-sol.html`（批量 + CSV/TXT 导出）、`wallet.html`（离线 EVM，含前后缀靓号）
- **余额检查**：`airdrop/testnet.html`、`airdrop/balance-trx.html`、`airdrop/balance-sol.html`
- **部署与合约**：`deploy.html`（编译 + 部署）、`deploybot.html`（策略自动化执行台）
- **协议与实验**：`send.html`（以太坊转账全景 / CREATE2）、`aa.html`（账号抽象体验台）
- **其他**：`tool/testnet.html`（测试网信息速查）、`text/index.html`（全链存证 DApp）

### 2.2 依赖与技术栈

全部通过 CDN 加载，无 `package.json`、无打包：

- **EVM**：`ethers` v6，已统一锁定到 `6.15.0`（cdnjs）
- **TRON**：`tronweb@5.3.2`（unpkg）
- **Solana**：`@solana/web3.js@1.99.0`（jsdelivr，稳定最新版；v2/v3 仍为 preview/rc）+ `bs58@5`
- **账号抽象**：`viem@2.44.4`（esm.sh，含 account-abstraction 模块）
- **合约编译**：`solc@0.8.30`（esm.sh）
- **DApp 框架**：`vue@3.5.22`（bootcdn）+ `marked` + `dompurify`（bootcdn）+ 本地 `vendor/tailwind.min.js`

> 观察：依赖版本已在后续维护中统一锁定，详见 README 的「依赖版本约定」；`text/archive/` 保留历史版本不升级。

### 2.3 核心一：OmniVerse 全链存证 DApp（`text/`）

这是区块链线里架构最完整的一个子项目，README 自称 V13。

**分层清晰**：

```
text/
├─ index.html      # 视图层（Vue 模板 + Tailwind）
├─ logic.js        # 业务逻辑（Vue Composition API setup）
├─ config.js       # 唯一网络配置源（window.NETWORKS）
├─ config6.js      # 兼容层：把 window.NETWORKS 映射为旧页面可读的 NETWORKS
├─ vendor/         # 本地化的 tailwind.min.js（不依赖外网）
├─ v4/v5/v6.sol    # 合约源码（UUPS 可升级）
├─ v5ABI.json / v6abi.json
└─ archive/        # 历史版本页面归档
```

**合约层（`v6.sol`）**：

- 继承 OpenZeppelin Upgradeable 的 `Initializable` + `UUPSUpgradeable` + `OwnableUpgradeable`，走 **UUPS 代理升级**模式
- 关键设计：**存储布局与 V5 兼容**，V6 只在 `Post` 结构体尾部追加 `coverImageUrl` / `imageCount`，这是可升级合约的标准做法
- 权限模型三层：`register`（注册昵称才能发帖）、`onlyActiveUser`（未注册 / 被封禁拦截）、`onlyOwner`（封禁解封、升级授权）
- 删除是**逻辑删除**：`exists = false` 且 `content = "deleted"`，但 `title` / 图片字段仍留在链上

**前端层（`logic.js`）的几处巧思**：

1. **双 ABI 动态切换**：`isV6Net(cid)` 判断后自动选 `V6_ABI` 或 `V5_ABI`，同一套代码兼容两种合约。
2. **多 RPC 故障转移**：`runReadOnNetwork` 遍历 `rpc` 候选列表，配合 `withTimeout`（12s）逐个重试，全挂才抛错——很实用的抗抖动设计。
3. **多链并发聚合**：`Promise.all` 同时抓多个链的最新帖子，按 `createdAt` 归并排序。
4. **双模式钱包**：MetaMask（`BrowserProvider`）或本地私钥（`ethers.Wallet`），后者把私钥明文存 `localStorage`。
5. **Deep Link 只读分享**：`?chain=0x..&id=10`，访客不连钱包也能通过 RPC 读内容。
6. **XSS 防护**：`marked` 渲染 Markdown 后经 `DOMPurify.sanitize` 清洗。
7. **余额监控**：30s 轮询，低于 `0.0001` 触发红色充值提醒，`onUnmounted` 清理定时器。

**该子项目的风险点**：

- ⚠️ 本地私钥模式：私钥明文存 `localStorage`，一旦 XSS 即失守。README 已自述「仅测试网」，但主网链（Gnosis / opBNB）在同一份配置里，**没有技术层面的硬拦截**。
- `sanitizeHtml` 的降级实现（无 DOMPurify 时）只做了简单正则，防护强度不足。
- `getPaginatedPosts` 返回整个 `Post[]` 结构体数组（含完整正文），链上 view 调用和 RPC 带宽成本偏高；且翻页靠 `page` 递增、无总数游标。
- 逻辑删除后 `title` / 封面图仍可读，隐私语义与用户预期可能不一致。
- 多个网络复用同一个代理地址（`0x177D8DCA…` 或 `0x7d342C7A…`），属设计选择但需注意部署一致性。

### 2.4 核心二：DeployBot 策略执行台（`web3/deploybot.html`）

这是工程复杂度最高的一个页面（1200+ 行），把「编译—生成—分发—部署」做成了一条流水线。

**前端编译**：`solc-compile-worker.js` 是一个 ES Module Worker，从 esm.sh 拉 `solc@0.8.30`，开启 optimizer（runs 200），通过 `postMessage` 把源码编译成 ABI + bytecode。主线程用 `new Worker(url, { type: 'module' })` 调用，**编译不阻塞 UI**。

**三种分发策略**（后续新增「一夫当关」，共四种）：

| 策略 | 语义 | 实现要点 |
|---|---|---|
| 蜻蜓点水 dragonfly | 按比例留存，其余分发 | 百分比范围 (0, 0.99] |
| 工厂分发 factory | 部署 `ETHTransferFactory`，调用 `Airdrop(recipients, amount)` 批量转账 | 分批 `batchSize`、gasLimit 12M |
| 二叉树 binary | 逐轮把节点余额随机拆成 A/B 两个新钱包，循环 N 轮 | 随机比例 0.01–0.99，单笔 < 0.0001 ETH 即「分支终止」 |
| 一夫当关 onetoMany | 1:N 普通转账，主钱包向每个分钱包发送相同金额 | 单线程顺序发送 + 自增 nonce，发完不逐笔等确认、最后统一等上链；先生成后发送 / 边生成边发送直到耗尽；gasLimit 固定 500000，余额预留按 21000 gas × maxFeePerGas（EIP-1559 下为手续费硬上界） |

**网络层**：内置 22 个常见测试网（取自 `text/config.js` 的 testnet 项），支持「自定义 RPC」接入未列出网络，并可用「备用 RPC」追加多节点，由 `FallbackProvider`（quorum=1）做自动故障转移。

**工程细节**：

- `runWithConcurrency(items, limit, worker)` —— 自实现的并发池，控制同时进行的任务数
- `getAdaptiveFeeOverrides()` —— 自适应 Gas：优先 EIP-1559，失败回退 legacy `gasPrice`，再回退裸调用，三层降级
- 每笔钱包状态落表（策略 / 地址 / 状态 / 备注），支持 CSV / TXT 导出
- 合约侧提供 `transferETH` / `Airdrop` / `batchTransferETHVariable` / `getBalance`

> ⚠️ 这是全项目**风险最高的页面**：批量生成私钥、明文导出、自动化批量转账三者叠加。任何执行都应严格限定在自建测试网，且私钥文件绝不能落公共设备。

### 2.5 核心三：以太坊转账全景（`web3/send.html`）

用四条路径串起「一笔钱从 A 到 B」的全部形态：

1. EOA 普通转账
2. 合约调用转账
3. 合约批量转账
4. **CREATE2 定制地址（靓号）** —— 最有技术含量的一段

CREATE2 地址预测的实现是教科书级的：

```js
const initCodeHash = ethers.keccak256("0x" + initCode);
const salt = ethers.zeroPadValue(ethers.toBeHex(nonce), 32);
const concat = ethers.solidityPacked(
  ["bytes1", "address", "bytes32", "bytes32"],
  ["0xff", factoryAddr, salt, initCodeHash]
);
const addr = "0x" + ethers.keccak256(concat).slice(26); // 取后 20 字节
```

即 `keccak256(0xff ++ factory ++ salt ++ keccak256(initCode))` 后取低 20 字节，然后暴力搜 `salt` 直到地址命中目标前后缀。这是纯前端实现的 vanity address 生成器。

### 2.6 核心四：AA 账号体验台（`web3/aa.html`）

基于 `viem` 的 account-abstraction 模块，完整走通 ERC-4337 流程：

- **EntryPoint 0.7**（`entryPoint07Address`）
- **Bundler**：Pimlico（`createBundlerClient` + `http(pimlicoUrl)`）
- **Paymaster**：可开关的 Gas 代付（`sponsorGas`）
- 流程：构造 `UserOperation` → 估算 Gas（`estimateUserOperationGas`）→ 签名发送 → 轮询 `UserOperationReceipt`

页面对「Paymaster 只赞助 Gas、不赞助转账金额」做了明确提示，说明作者清楚常见误区。

### 2.7 核心五：钱包生成 / 转账 / 余额检查

- **`wallet.html`**：离线 EVM 生成器，支持普通生成与前后缀定制靓号，批量导出 CSV
- **`wallet-evm/trx/sol.html`**：三条链的批量生成，输出私钥 + 地址
- **`transfer*.html`**：三条链的测试网转账，EVM 支持 21 个测试网 + 自定义 RPC
- **`airdrop/testnet.html`**：一个值得注意的实现——**不用 ethers**，直接 `fetch` 发 JSON-RPC `eth_getBalance`。配合「线程数」（默认 50）分批并发、进度条、CSV 导出，是极轻量的批量查询方案。
- **`deploy.html`**：前端 `solc` 编译 + MetaMask 部署，**硬编码只允许 Sepolia**（`chainId !== CHAIN_ID` 直接阻止），是个有意识的安全约束。

### 2.8 区块链线的共性工程模式

1. **Zero Build**：无 npm、无打包，CDN 直连，`esm.sh` 承担了「裸模块」的角色（solc / viem）。
2. **Worker 隔离**：重计算（solc 编译）放 Worker，避免卡死主线程。
3. **降级思维**：RPC 多候选重试、Gas 三层回退、`Promise.all` 容错——到处是「失败也不能白屏」的防御。
4. **配置外置**：`text/config.js` 是唯一配置源，新增链只改一处，README 明确要求避免配置漂移。
5. **导出友好**：几乎每个工具都提供 CSV / TXT 导出。

## 三、视觉交互部分

### 3.1 模块地图

- **`camera/picture/index.html`** —— 人脸追踪图库（点头 / 摇头无接触交互）
- **`camera/smokeflower/index.html` / `index2.html` / `index3.html`** —— 手势烟火 AR（三个迭代版本）
- **`qifu/index.html`** —— 赛博祈福轻交互页

### 3.2 人脸追踪图库：用头当遥控器

**技术底座**：MediaPipe `FaceMesh` + `camera_utils`，`maxNumFaces: 1`、`refineLandmarks: true`。

**交互算法**（关键在 `onResults` 回调）：

- 取**鼻尖 landmark[1]** 作为头部姿态代理点，映射到百分比坐标
- 采样节流：`dt > 50ms` 才判定一次，避免高频抖动
- 动作阈值：水平位移 `|dx| > 3.5` 判「摇头」，垂直位移 `|dy| > 2.5` 判「点头」
- **1 秒冷却**（`cooldown`）防止一次动作连环触发

**状态机**：

```
preview（左上小图） --点头--> fullscreen（80vw 大图）
fullscreen --摇头--> preview
preview --摇头--> 切换到下一张图
```

摄像头画面用 `transform: scaleX(-1)` 做镜像，符合照镜子的直觉。素材为 `img/1~3.png`。

**评价**：用单点位移阈值做姿态识别，胜在极简、零依赖模型训练；缺点是阈值对距离 / 头型不鲁棒，不同人不同距离的触发灵敏度会漂移。

### 3.3 手势烟火 AR：三版迭代对比

三版共用同一套「MediaPipe Hands + Canvas 粒子」骨架，差异在参数与粒子引擎：

| 版本 | 捏合阈值 | maxNumHands | 粒子实现 | 特点 |
|---|---|---|---|---|
| `index.html` | 40px | 2 | 多色随机 | 初版，捏合绽放 |
| `index2.html` | 35px | 1 | 基础粒子 | 单手中，更保守 |
| `index3.html` | 40px | 2 | **Particle 类**（曳尾 + 摩擦 + 重力 + 衰减） | 最终版，最完整 |

**手势判定**：取拇指尖 `landmarks[4]` 与食指尖 `landmarks[8]`，算欧氏距离 `Math.hypot()`，小于阈值即判「捏合」。

**`index3.html` 的粒子引擎**（值得单独说）：

- 每次爆炸生成 **100 个粒子**，随机色相 `hue`（`hsla` 着色）
- 每个粒子维护 `history` 数组（最多 15 帧）绘制**曳尾轨迹**
- 物理：`friction = 0.94` 空气阻力、`gravity = 0.2` 重力、`alpha` 线性衰减
- 头部额外画一个明亮核心点，模拟高温光斑
- 关键渲染技巧：粒子阶段切到 `globalCompositeOperation = 'lighter'`，让烟火在视频画面上产生**真实的光学叠加**（加色混合），结束后复位 `source-over`

**边沿触发**：`isPinched` 标志位保证「一次捏合 = 一次爆炸」，避免捏住不放导致连续爆。指尖还会画半透明白点做操作提示。

### 3.4 赛博祈福：不写 JSX 的 React 应用

这个页面有个很有意思的技术选择——**用 React 19 但不写 JSX**：

- 通过 `<script type="importmap">` 把 `react` / `react-dom` 映射到 `esm.sh`
- 用 `React.createElement`（别名 `el`）手写虚拟 DOM，**彻底规避 JSX 编译**，保持 Zero Build
- 完整实现：神仙轮播（6 位：观世音 / 财神 / 月老 / 文曲星 / 妈祖 / 关帝）、供品三选一、祈福文本域、提交动画
- 数据用 `localStorage` 的 `blessing_history` 持久化，渲染成「功德簿」
- 图片资源托管在 `cdn.120.show/qifu/`

**评价**：这是「Zero Build 约束下的 React 妥协方案」——`React.createElement` 可读性远不如 JSX，但它换来了「无构建步骤」的一致性，属于有意识的取舍。

### 3.5 视觉交互线的共性

1. **同一套明亮动漫风设计系统**：`--pink / --peach / --blue / --mint / --lavender` 五色 + 渐变文字 + 圆角卡片 + 光斑背景，与主页、Web3 合集页完全一致（`qifu` 页也复用了这套变量）。
2. **AI 能力全靠 MediaPipe**：人脸 / 手势识别都是浏览器端推理，不上传任何画面。
3. **运行前提明确**：需摄像头授权 + 能访问 `cdn.jsdelivr.net`（模型文件）。
4. **无模型版本锁定**：MediaPipe 与模型文件都走 `@latest` 语义的 CDN 路径，存在未来行为漂移风险。

## 四、跨模块观察与建议

### 优点

- **架构一致性高**：两条线共享同一套视觉语言，站点整体感强
- **零构建、零后端**：任意静态托管即可跑，部署成本极低
- **防御性编程**：多 RPC 重试、Gas 多层回退、`Promise.all` 容错、Worker 隔离重计算
- **安全有意识**：`deploy.html` 硬锁 Sepolia、DApp 用 DOMPurify 清洗、README 明确标注私钥模式风险
- **文档与配置管理规范**：`text/config.js` 单一配置源 + `archive/` 归档历史版本

### 风险与改进建议

| 优先级 | 问题 | 建议 |
|---|---|---|
| 高 | `ethers` 多版本并存、`@solana/web3.js` 用 `@latest` | ✅ 已处理：ethers 统一 `6.15.0`，solana 锁定 `1.99.0`，并写入 README 依赖清单 |
| 高 | 本地私钥明文存 `localStorage`，且未按链做硬隔离 | 主网链禁用私钥模式；或改用 WebCrypto 加密存储（用户评估后认为测试网可接受） |
| 高 | DeployBot 批量生成 / 导出明文私钥 | 增加二次确认与风险提示；导出前要求显式确认 |
| 中 | 逻辑删除后 `title` / 封面仍可读 | 若语义是「删除」，应一并清空或明确告知用户 |
| 中 | `getPaginatedPosts` 返回完整 struct 数组 | 改为返回 ID 列表 + 按需读取，降低 RPC 负载 |
| 中 | MediaPipe / 模型文件未锁版本 | 锁定具体版本号，避免 CDN 行为漂移 |
| 低 | 各页 CSS / JS 大量重复 | 抽公共样式与工具函数，减少维护面 |
| 低 | 仓库未声明统一 License | README 已提示，建议补 `LICENSE` 并明确各子模块范围 |
