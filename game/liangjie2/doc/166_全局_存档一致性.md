# 166 存档一致性与事务规则
1. 交易事务包含报价、预留、付款、税务、运输和交付步骤。
2. 每步使用同一 transaction_id 和独立 idempotency_key。
3. 重复请求返回已有结果，不重复扣款或增加库存。
4. 付款失败释放预留，但保留失败审计记录。
5. 发运后失败不回滚物理位置，转入异常货物流程。
6. 世界切换前写入两个 world_clock 和待处理事件队列。
7. 读档时校验库存账、资金账、税务账和货运账守恒。
8. 校验失败将存档标为 needs_repair，不自动猜测修正。
9. 修复工具只能通过补偿事件更正，不改写旧日志。
10. 价格版本随订单冻结，后续调价不影响已付订单。
11. 路线版本随发运冻结，改道创建新的路线修订。
12. NPC 日程版本随事件保存，避免读档后瞬移。
13. null 与 unavailable 原样序列化，不转换成数值 0。
14. 所有金额保存货币和最小单位，禁止裸浮点数。
15. 存档迁移记录 from_version、to_version 和 checksum。
16. 测试覆盖崩溃恢复、重复提交、切界和跨年结算。
